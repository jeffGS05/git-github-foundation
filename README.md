## Git Workflow

This repository follows a structured Git workflow designed to simulate professional software engineering practices.

### Branching Strategy

The `main` branch represents the stable version of the repository.

Changes are developed in dedicated branches using descriptive names:

```text
feature/<description>
fix/<description>
docs/<description>
chore/<description>
```

### Commit Convention

Commits follow a Conventional Commits style:

```text
feat: add functionality
fix: correct an issue
docs: update documentation
chore: maintenance changes
ci: update CI configuration
security: improve security controls
refactor: restructure existing code
```

### Pull Requests

Changes should be reviewed through Pull Requests before being merged into `main`.

The general workflow is:

```text
Issue
  ↓
Feature Branch
  ↓
Changes
  ↓
Commit
  ↓
Push
  ↓
Pull Request
  ↓
Review
  ↓
Merge
```

This workflow helps maintain a clean project history and provides traceability between requirements and implementation.
